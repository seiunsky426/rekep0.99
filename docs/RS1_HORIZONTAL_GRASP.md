# RS1 可见表面上的水平抓取

抓取节点现在根据 RS1 可见侧面生成水平接近方向，再筛选两指闭合方向、接触位置及 Piper 实体夹爪与桌面的间隙。关键点确定目标实例和部位，不要求 TCP 与关键点精确重合。现有连续 IK、全臂碰撞、ESDF 和执行反馈检查继续保留。

## 当前规则

| 项目 | 实现 |
| --- | --- |
| 输入 | RS1 场景点云；背景点保留用于碰撞检测 |
| 目标区域 | 已分割的可见目标点，局部法向可靠且属于侧面，并高于桌面及夹爪半高所需间隙 |
| 桌面 | 对目标附近非目标点做确定性 RANSAC 和平面拟合；证据不足时拒绝生成，不假设桌面为 z=0 |
| 方向 | 从可见侧面法向估计最多两个闭合轴，生成与之垂直的水平接近轴 |
| 坐标转换 | `a_camera = R_base_from_camera.T @ a_base`；向量不加平移，不固定写相机 `[0,0,1]` |
| 水平角度 | 接近轴和闭合轴各偏离基坐标系 XY 平面不超过 10°；拒绝向上接近 |
| 接触 | 两接触参考点均距离观测到的目标表面不超过 5 mm；闭合轴与局部法向偏差不超过 20°；目标在闭合轴两侧均有支持点 |
| 张开 | 按 URDF 总开口限制张开，两指参考点与目标观测表面至少间隔 3 mm；正式路径仍检查完整夹爪碰撞 |
| 桌面间隙 | 两个接触参考点、预张开状态下完整手指和掌部网格均至少高于拟合桌面 3 mm |
| SDK | 正式节点始终开启碰撞筛选；按表面估计的方向分别进行 dense 推理 |

`maximum_horizontal_angle_deg` 在 `system.launch` 中设为 10；原来的向下 30° 设置已替换。

## Piper 几何来源

用户确认安装的夹爪与 URDF 一致。`PiperGripperGeometry` 从当前 `/robot_description` 和其碰撞网格加载尺寸及运动变换，正式节点将读取的开口上限和手指包络高度传给 SDK。

此次仓库模型读数：

- 总开口：70 mm，由两个 35 mm 指关节行程得到。
- 夹爪基座到 `rekep_tcp`：135.8 mm。
- 手指网格沿接近轴的总跨度：约 76.50 mm。
- TCP 到掌部前界：约 72.80 mm，作为插入深度上限之一。
- 手指网格最大厚度包络：约 56.00 mm。手指形状沿长度变化，SDK 使用这一保守包络；完整网格用于桌面检查。

AnyGrasp 输出的 `depth` 是每个候选的插入深度，不是手指物理长度。仍按官方定义 `translation + depth * approach_axis` 计算指尖参考中心，再映射到 Piper TCP。未手动旋转或平移网络候选来使其通过检查。

## 同一 RS1 快照的复跑结果

证据目录：`runtime/evidence/m8_fresh_pipeline_20260916T031228Z/horizontal_grasps/`。

- 保持输入 30000 点不变；原目标 2590 点，新的可见侧面区域 476 点。
- 两个方向在关闭 SDK 碰撞筛选的诊断中分别返回 156 和 116 个候选，共 272 个。
- 同时满足水平接近、水平闭合及不向上接近的有 16 个，其中 12 个通过完整夹爪桌面间隙检查。
- 全部几何条件通过数为 0；两个方向开启 SDK 碰撞筛选时也均返回 0。
- RViz 展示的代表候选 `side1_collision_off-47` 满足方向与桌面条件，但两个接触参考点距观测表面约 15.25 mm、5.14 mm，法向偏差约 30.8°、30.6°，仍被拒绝。

这是本轮候选不满足要求的证据，不证明场景中不存在可行抓取。单相机缺少另一侧表面时，不将未观测表面补成已验证接触。

## 可视化与验证

RViz 配置：证据目录中的 `horizontal_grasps.rviz`。

- 洋红色：允许生成候选的 RS1 可见侧面点。
- 红色线框：方向要求未通过。
- 黄色线框：方向要求通过，但仍未通过全部检查。
- 实体夹爪：一个被拒绝的代表候选，使用 Piper 原生掌部和两指碰撞网格。
- 半透明平面：本轮拟合桌面，仅用于诊断，不发布为已验收标定。

`report.json` 保存各候选的逐项几何结果，`verification.json` 记录实际收到的 ROS 可视化话题。复跑使用已保存快照，未采集新的相机帧。

软件验证：仓库审计、launch 路径审计、Catkin 329 项测试通过。新增覆盖水平接近与闭合的独立检查、向上接近拒绝、接触支持、掌部穿桌、缺少桌面、深度限制、倾斜相机转换和真实 URDF 几何。

`hardware_commands_sent=false`，`motion_allowed=false`。没有候选获准交给 PathSolver，也没有物理抓取成功结论。
